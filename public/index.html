MULTI-AGENT ORCHESTRATION

多个 Agent，像一支队伍一样工作

不是把一个模型复制七遍，而是让不同角色共享同一套会话、工具与权限边界。指挥官拆目标，规划者排步骤，执行者动手，验证者把关；需要并行时，子代理接手独立任务。

  • 多聊天室 Agent 并存，权限按聊天室归属，互不越界。
  • chat_handoff 把任务连同上下文交给另一个已配置 Agent。
  • 子代理并行处理独立子任务，结果回到主线继续编排。

COMPUTER USE

看得懂桌面，也点得准按钮

  • UIA + 视觉坐标解析，窗口缩放与多分辨率下仍能对准目标。
  • 安全点击、回收站删除、默认工程保护，误删路径被堵死。
  • 外部目录写入逐次审批；完全访问需二次确认且重启失效。

BROWSER USE

把浏览器变成 Agent 的另一双手

浏览器桥接让 Agent 操作真实网页，而不是只抓一段 HTML：语义定位元素、输入、点击、滑块、拖拽、组合键，按标签页租约隔离任务，结束后归还。

  • DOM 语义定位优先，视觉兜底，复杂控件也能操作。
  • 标签页租约避免多个任务互相抢页面；只关闭自己创建的标签。
  • 受限的内部页与扩展页不直接操作，边界清晰。

PERMISSION & SECURITY AUDIT

每一次放行，都留下证据

权限不是一句「允许访问」，而是一条可审计的链路：请求进入闸门，按聊天室与路径策略评估，高危动作等待人工批准，执行结果写回 outcome.permission_gate。

  • 未知权限元数据 fail-closed，不默放；hook 独立授权并留痕。
  • 审批可携带 updatedInput / updatedPermissions，批准后仍重走闸门。
  • 可选 Windows 低完整性沙箱，把写入边界变成系统级约束。

GOAL PIPELINE

把长任务拆成可验收的四个阶段

Goal 模式不是「一直跑到模型说完成」，而是 commander → planner → implementer → verifier 的确定性流水线：验证门不过就带着原因回退重改，重试有上限，预算不被重置。

  • 验证门支持 FilesExist / Command，产出必须通过真实检查。
  • implementer 受阻回 planner 重规划；verifier 不通过回 implementer 重改。
  • 阶段状态落 SQLite，可暂停、恢复、人工验收。

PROVIDER ACCESS

一个总线，接住所有模态

  • 多模态与文本：Agnes 3.0 Flash、OpenAI 兼容、Devin、ChatGPT 订阅。
  • 生图 / 生视频：Agnes Image / Video、OpenRouter 渠道。
  • 本地：Ollama 或任意自定义 OpenAI 兼容端点，数据不出内网。
