coolzhuagent ↔ Claude Code harness 对比

对 Claude Desktop/CLI 的已安装产物做了纯静态逆向分析（不联网、不调用模型、 不绕过完整性保护），并把还原出的 harness 组件逐项与本仓库代码比对。结论： 骨架高度同构——多数"替换"是字段级补齐，而不是重写。以下为公开摘要。

总体判定

分档含义规模
直接替换设计可直接落到现有结构，改动边界清晰~10 项
借鉴改造模式好但需适配 Rust/现有抽象~8 项
coolzhu 更强现有实现已优于对侧，保留7 项
不建议与现有架构冲突或收益低4 项

coolzhuagent 已更强的部分

  • hook 独立执行授权：未授权不运行且留痕——Claude 的 settings.json 命令即跑，无此层。
  • hook 跑过 → 原审批作废重判：hook 可改世界，PreToolUse 之后必须重评。
  • 闸门报告写回：outcome.permission_gate = gate，防 executor 伪造审批结果。
  • Unspecified fail-closed：未知权限元数据一律按配置错误处理，不默放。
  • memory beads：嵌入相似度 / supersede / TTL / recall 评分，胜过平文件记忆。
  • install_transaction：插件原子安装事务。
  • WindowsLowIntegrity：低完整性写边界，比路径检查硬。

不建议移植

  • Electron IPC 服务注册表 co()——本产品是 HTTP 边界（web-console + agent-server Router）。
  • CLI 子进程 per-session——同进程 ConversationRuntime 已等价且更轻。
  • RTB 设备桥——与本仓 remote.rs UpstreamProxy 方向相反。
  • Hyper-V microVM——低完整性路线更贴 Windows 单机架构。

方法论

分析全程离线只读：复制安装产物 → 解包 app.asar → 静态分析（约 1,599 个 IPC 操作、 54 个 contextBridge API、70 条 sender 校验、42 个内置工具定义、系统 prompt 装配与 12 项停因闭集）。遇加密/完整性校验/凭据边界即停止记录，不做绕过。原始报告与 完整比对表在分析仓（非公开分发）。
